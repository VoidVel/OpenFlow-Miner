The problem

Every process has two versions.

There's the documented process — the diagram in the onboarding deck — and the actual process, the one that really happens: the rework loops, the bottleneck steps, the unofficial workarounds that quietly became load-bearing.

The gap between them is where operational cost hides. Finding it usually means expensive enterprise tooling or slow, subjective interviews. OpenFlow Miner is the free, developer-friendly way to just point raw event data at a tool and get an honest answer.

What it does

Four insights from one event log

Process graph

The directly-follows graph: which step actually leads to which, weighted by how often.

Variants

The distinct end-to-end paths cases really took, ranked by how common each is.

Statistics

Case and event counts, average and median durations, most common start and end steps.

Bottlenecks

The steps where time actually piles up — a starting signal for where delay concentrates.

Domain-agnostic by construction

A hospital, a game studio, and a support team use the exact same API.

The core model can express only case, activity, and timestamp (plus an optional actor and a generic attribute bag). It has no way to represent an order status or a claim type — that's enforced by a test, not by good intentions. Whatever your industry, the tool never needs to know what it is.

Infrastructure, not an application

The API is the product.

Everything is reachable with curl and the docs alone. The live demo and this site are just reference clients — delete them and the product is intact. The mining engine is a standalone .NET library with zero third-party dependencies, embeddable in any project.
